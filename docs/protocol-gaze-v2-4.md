# V2.4：阅读视线与 Pencil 动作序列（可选探索）

## 研究问题与证据边界

1. 阅读新闻、图文流、短视频时，视线在内容对象上的时间加权热区与 Pencil 悬停热区有多大重合？两种传感器分别报告有效覆盖时间，不能用回调点数比较。
2. 主动 Hover 是否比自然阅读更常出现“看向目标 → 笔尖移向目标并减速 → 目标内确认 → 笔尖移向下一个目标”的**顺序关系**？B1 菜单出现后视线可转向菜单项；B3 可在 Pencil 确认前预看下一目标；B4 的视线可能扫视目标集合。因此不要求每一帧视线与 Pencil 同位。
3. 在留出的 C1–C3 同对象任务中，加入视线证据后，能否在保持主动任务召回率的同时减少自然阅读的规则触发候选？自然阅读候选只是“可能误触”，不是经访谈确认的真实误触；任务条件只是意图代理标签。

## 硬件与采集

现用 12.9 英寸第六代 iPad Pro 有前置 TrueDepth 摄像头。ARKit `ARFaceTrackingConfiguration` 的 `ARFaceAnchor.lookAtPoint` 与双眼变换给出估计朝向，**不是现成的屏幕注视坐标或可靠的 48×48 pt 对象命中**。当前手机区处于横屏右下方，摄像头离该区域较远；必须在相同持握、距离、光照下测量误差。

- 配置中的“记录视线（试验）”默认关闭。开启后“开始实验”自动进入 9 个手机区校准点、4 个独立验证点；每点先稳定再取有效帧。无需触屏确认点。姿势改变、应用后台返回后重新校准。
- 校准记录原始相机相对视线射线与拟合系数，验证记录中位、P90 像素/pt 误差、有效帧比例和未完成点。验证点不参与拟合；校准 ID 挂在所有视线样本上。预设小对象分析门槛为 P90 ≤24 pt 且有效帧比例 ≥70%，这是**试运行验收目标，不是该设备已达到的性能**。若未达到，仍保存探索性视线数据，但不作 48 pt 同对象判断；可改为较大段落/卡片区域或专用眼动仪。
- 每个前摄帧保存相机帧时间、接收时的系统单调时间、原始射线投到相机平面的坐标、校准后的全屏及手机局部 XY、有效/丢失原因、校准 ID 和当前内容对象 ID。相机帧时间的零点与 Pencil 系统时间是否一致由实测对齐检查，不能直接假设；分析优先使用同设备记录的时间映射并报告偏移/抖动。
- 视线为 `SAMPLE`，`inputType=GAZE`、`sampleSource=FRONT_CAMERA_GAZE`；原有 56 列不变，额外字段放版本化 metadata。`GAZE_CALIBRATION`、`GAZE_UNAVAILABLE`、`GAZE_TRACKING_LOST/RESUMED` 为事件。摄像头拒绝、脸离开画面、眼睛被遮挡、校准不良均明确标缺失，不写伪坐标。
- 默认只保存坐标和质量信息，不保存面部视频、RGB 帧、深度图或面部网格。界面在配置处说明用途与本机保存方式，系统相机权限说明与隐私文档保持一致。导出仍由用户操作，原始视线数据不进入公开 GitHub 报告。

## 任务安排

沿用 A1–A7、B1–B4、C1–C3 的任务和既定成功判定；视线收集不触发、阻断、延时菜单或自动跳题。

| 阶段 | 最小采集 | 对照目标 |
|---|---|---|
| 校准/质检 | 每次开始或后台恢复时做 9 点拟合 + 4 点验证；换姿势另起会话 | 检查初始位置误差及有效追踪覆盖 |
| 自然基线 | A5 新闻、A6 图文、A7 视频各 120 秒 | 同场景视线与 Pencil 热区、Home、自然候选 |
| 主动操作 | B1 菜单、B2 指向、B3 多选、B4 圈选 | 目标间视觉先行、接近、确认、转移 |
| 留出验证 | C1–C3 各条件，同内容/小对象边界 | Pencil-only 与 Pencil+gaze 对照，报告拒判率 |

自然阅读的画面不显示视线光标或倒计时，不改变阅读方式。建议先 A 自然基线，再 B 主动，最后 C；按姿势分区组，顺序在参与者间配平。至少在不同参与者/不同会话上验证，单人两天只能算探索性试运行。

本版还没有在每段阅读结束后自动复测校准；样本记录距校准完成的秒数，长时间漂移只能作为待检风险。真机试运行应在阅读结束后另开短会话复测，再决定是否加入无干扰的段间复测流程。

## 分析定义

- “视觉热区”和“Pencil 热区”各以手机局部同一 20 pt XY 网格、相同场景时段、有效采样间隔计时；另列总时长、追踪缺口、手机外时长。滚动/翻页/视频切换后按当时内容对象真实边界重算对象命中，不能将固定屏幕坐标误作固定内容对象。
- 眼手同对象按**时间窗及对象 ID**比较，而不是逐帧两点重合。预注册候选：Pencil 进入对象前 300 ms 到确认时，视线曾在该对象内有有效凝视；再报告视线领先/落后时间、视线缺失、目标切换。窗口需做 0/150/300/500 ms 敏感性检查。需要连续追踪和独立校准质量通过，不能以低质量视线给任务判失败。
- “移向目标”从离开上一位置到首次进入目标；“确认”是 `TOUCH_DOWN`、`MENU_OPEN` 或 `HOVER_SELECT` 的实际事件；“移向下一个”从离开当前目标到下一对象首次进入。B4 独立分析完整圈线与闭合，不能硬套停留阶段。
- 新 App 在试次成功或失败后的间隔继续记录 Pencil 与已开启的视线样本，标记 `sequencePhase=INTER_TRIAL`；下一次 `TRIAL_START` 保存 `previousTrialID` 和 `transitionKind`。分析可沿同一会话追踪到下一目标出现后的动作，但只连接时间连续、来源一致且无缺口的实测点。旧两日数据缺少这段试次间样本，报告中的 Touch 后半段如实留空。
- Touch、阅读 Home、主动 Hover 三列图采用同一 XY 速度纵轴、50 ms 时间箱；分别以触屏、Home 区首次进入、悬停选择为 0 点。Home 是回顾性空间参考，**没有确认动作**。首图画目标/Home 中心距离及速度；色带与有效事件数展示不确定度，详细速度/Z 原始曲线保留折叠证据。
- 对照 Pencil-only M0、Pencil+gaze M1：按场景/姿势报告自然候选每分钟、主动任务召回率、漏触率、判定延迟与 gaze coverage。任务标签与心理意图真值分列；模型/阈值在 A/B 开发后冻结，只在留出的 C 和独立参与者上估计性能。视线缺失时单列 `ABSTAIN`，不并入阴性。

## 上线判断

本版只做**采集与离线对照**。只有在真机取得可复现的校准精度、有效追踪覆盖，以及独立参与者 C 条件验证后，才考虑把眼手证据用于在线判定；即便通过，也应支持快速反馈与撤销。视觉注意不等于选择意图，更不等于执行授权。
